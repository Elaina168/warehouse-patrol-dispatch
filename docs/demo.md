## 推荐场景

主线演示使用唯一前端场景：

```text
integrated-demo
```

当前前端只暴露 `综合调度演示`，它把原先分散在多个场景里的能力合并到同一条仿真流程：

`integrated-demo` 使用 `26 × 16` 网格，包含12组 `3 × 2` 货架，共72个不可通行的货架实体格。每个货架有一个唯一相邻作业格，机器人只在作业格完成取放。货架组、顶部进货点、底部出货点、右侧机器人起点和充电口之间统一保留两个完整可走格；除固定障碍和运行时封锁外，通道与作业格可通行。

四台默认机器人均显式支持 `inspection`、`delivery`、`emergency`，即巡检、取送、突发三类任务；悬浮任一机器人应看到精确提示“能力 巡检 / 取送 / 突发”。缺少 `capabilities` 的旧导入场景按全能力兼容，但显式字段必须使用上述三个值且不得为空或重复。主演示不使用异构分工改变既有分配结果。

- 巡检任务。
- 库存取送任务：入库从进货点送到空货架作业格，出库从已有货物货架作业格送到出货点。
- 狭窄通道避碰。
- 默认在线任务。
- 到达目标后的作业停留。
- 充电地块、机器人电量与容量状态；默认流程不要求实际触发充电。
- 可选的手动任务、运行时封锁、机器人故障及恢复接口。

推荐配置：

- 启用避碰规划。
- 主界面固定启用场景动态机制，没有动态事件开关。
- 使用在线会话，而不是只展示批量调度。

默认三项配送坐标固定为：

- `T1` 入库：进货点 `[2,0]` -> 货架 `[2,4]` 的作业格 `[2,5]`。
- `T2` 出库：货架 `[13,7]` 的作业格 `[13,6]` -> 出货点 `[2,15]`。
- `T4` 入库：进货点 `[8,0]` -> 货架 `[12,8]` 的作业格 `[12,9]`。

后端会话通过 `shelfStates` 维护并返回权威库存与预订状态：`empty`、`inboundReserved`、`occupied`、`outboundReserved`。前端仅据此显示库存；`occupied`、`outboundReserved` 亮起，另外两种状态不亮。手工任务和随机任务均使用统一任务端点并接受相同的后端库存校验。

## 演示步骤

1. 打开页面后确认后端状态为在线。
2. 依次悬浮四台机器人，确认都显示“能力 巡检 / 取送 / 突发”。
3. 确认初始12个货架显示库存高亮；默认 `T2` 对应货架虽已预订出库，仍保持高亮。
4. 点击播放，让时间持续推进，观察 `T1` 至 `T5` 的任务状态、机器人路径和“重规划解释”面板。
5. 播放到 `T=12`，确认默认队列中的 `E1` 进入执行状态。
6. 在 `T2` 机器人实际到达 `[13,6]` 取货时，确认货架 `S32` 熄灭，不等待其到达出货点。
7. 继续播放，确认 `T1`、`T4` 完成放货和作业时间后，货架 `S13`、`S43` 分别亮起。
8. 继续播放到 `T=700`，确认6个默认任务全部完成、最终13个货架有货，且冲突、失败、截止超期和充电访问均为0。
9. 如需展示算法对比，在同一综合场景里切换到“基线对比”，确认固定输入的预测冲突大于0，再切回“避碰规划”并确认预测冲突为0。

默认演示不追加运行时任务，不自动封锁单元，也不自动标记机器人故障。手工任务、随机任务、运行时封锁、机器人故障及恢复可在默认流程验收后作为独立扩展操作演示。手工与随机任务都提交到 `POST /api/sessions/{session_id}/tasks`；随机生成器对巡检和突发使用当前车队能力并集，随机配送还要求至少一台配送机器人满足固定 `demand: 1` 的载重，后端仍执行最终能力、配送载重和库存校验。

## 验收点

演示应覆盖以下能力：

- 在线会话创建。
- tick 推进与机器人状态更新。
- 任务目标点作业时间与完成后释放机器人。
- 主演示能查看充电地块、电量与容量；完整低电量充电闭环由专用低电量场景和自动化测试验收。
- 任务锁定。
- 默认六任务在线闭环。
- 四台默认机器人 tooltip 均显示“能力 巡检 / 取送 / 突发”，且所有任务分配都满足 `capabilities`；配送还满足 `robot.load >= task.demand`。
- 后端权威库存和四种货架状态；出库在实际取货时熄灭，入库在放货作业完成后亮起。
- 手工与随机配送使用统一任务端点和同一库存校验。
- 独立扩展测试中的高优先级任务抢占、运行时封锁、机器人故障与恢复。
- 事件日志解释。
- 指标历史变化。
- 同一综合场景下关闭避碰会出现预测冲突，开启避碰后预测冲突降为0。
- 同一规范化冲突连续被安全门拦截三次后，顶部状态显示“连续拦截 N 次，当前调度停滞”；该字段只负责诊断，不解除全车安全等待。

专项恢复测试中，唯一兼容机器人故障时任务应显示临时 `restoreRobot`；先恢复不兼容机器人不应清除失败，恢复兼容机器人后应自动重规划。该能力约束只改变机器人资格，与尚未实现的全规划时域零冲突保证无关。

避碰验收分为三个层级：一级是代码强制的在线执行安全，开启避碰时会在首个预测顶点或反向边冲突 tick 全车等待，不把冲突动作写入实际路径历史；二级是固定种子与当前综合场景输入的预测冲突为0；三级仍是未实现的全规划时域零冲突保证。大跨度 tick 请求会在首个危险 tick 提前返回，`SessionResult.safetyIntervention` 给出绝对时间、冲突类型、机器人和单元格。

当安全门拦截冲突时，播放自动暂停，顶部显示结构化拦截状态，地图高亮冲突单元和涉及机器人。检查事件后再次播放会从实际等待位置重新规划；系统不会降级执行带冲突路径。`integrated-demo` 默认流程保持不变，强制一维通道仅用于自动化回归，不加入持久化前端场景；基线对比、直接调度和实验接口仍可返回或执行预测冲突，用于对照。
