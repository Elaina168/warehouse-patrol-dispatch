本文档固定当前展示路线，避免演示时临时切换能力范围。

## 推荐场景

主线演示使用唯一前端场景：

```text
integrated-demo
```

当前前端只暴露 `综合调度演示`，它把原先分散在多个场景里的能力合并到同一条仿真流程：

`integrated-demo` 使用 `26 × 16` 网格，包含12组 `3 × 2` 货架，共72个不可通行的货架实体格。每个货架有一个唯一相邻作业格，机器人只在作业格完成取放。货架组、顶部进货点、底部出货点、右侧机器人起点和充电口之间统一保留两个完整可走格；除固定障碍和运行时封锁外，通道与作业格可通行。

四台默认机器人均显式支持 `inspection`、`delivery`、`emergency`，即巡检、取送、突发三类任务；悬浮任一机器人应看到精确提示“能力 巡检 / 取送 / 突发”。缺少 `capabilities` 的旧导入场景按全能力兼容，但显式字段必须使用上述三个值且不得为空或重复。主演示不使用异构分工改变既有分配结果。

- 巡检任务。
- 库存取送任务：入库从进货点送到空货架作业格，出库从已有货物货架作业格送到出货点。
- 狭窄通道避碰。
- 默认在线任务。
- 到达目标后的作业停留。
- 充电地块、机器人电量与容量状态；默认流程不要求实际触发充电。
- 可选的手动任务、运行时封锁、机器人故障及恢复接口。
- 可选的运行中机器人接入、任务完成后的安全永久退役和重置恢复。

推荐配置：

- 启用避碰规划。
- 主界面固定启用场景动态机制，没有动态事件开关。
- 使用在线会话，而不是只展示批量调度。

默认三项配送坐标固定为：

- `T1` 入库：进货点 `[2,0]` -> 货架 `[2,4]` 的作业格 `[2,5]`。
- `T2` 出库：货架 `[13,7]` 的作业格 `[13,6]` -> 出货点 `[2,15]`。
- `T4` 入库：进货点 `[8,0]` -> 货架 `[12,8]` 的作业格 `[12,9]`。

后端会话通过 `shelfStates` 维护并返回权威库存与预订状态：`empty`、`inboundReserved`、`occupied`、`outboundReserved`。前端仅据此显示库存；`occupied`、`outboundReserved` 亮起，另外两种状态不亮。手工任务和随机任务均使用统一任务端点并接受相同的后端库存校验。

## 演示步骤

1. 打开页面后确认后端状态为在线。
2. 依次悬浮四台机器人，确认都显示“能力 巡检 / 取送 / 突发”。
3. 确认初始12个货架显示库存高亮；默认 `T2` 对应货架虽已预订出库，仍保持高亮。
4. 点击播放，让时间持续推进，观察 `T1` 至 `T5` 的任务状态、机器人路径和“重规划解释”面板。
5. 播放到 `T=12`，确认默认队列中的 `E1` 进入执行状态。
6. 在 `T2` 机器人实际到达 `[13,6]` 取货时，确认货架 `S32` 熄灭，不等待其到达出货点。
7. 继续播放，确认 `T1`、`T4` 完成放货和作业时间后，货架 `S13`、`S43` 分别亮起。
8. 继续播放到 `T=700`，确认6个默认任务全部完成、最终13个货架有货，且冲突、失败、截止超期和充电访问均为0。
9. 如需展示算法对比，在同一综合场景里切换到“基线对比”，确认固定输入的预测冲突大于0，再切回“避碰规划”并确认预测冲突为0。

默认演示不追加运行时任务，不自动封锁单元，也不自动标记机器人故障。手工任务、随机任务、运行时封锁、机器人故障及恢复可在默认流程验收后作为独立扩展操作演示。手工与随机任务都提交到 `POST /api/sessions/{session_id}/tasks`；随机生成器对巡检和突发使用当前车队能力并集，随机配送还要求至少一台配送机器人满足固定 `demand: 1` 的载重，后端仍执行最终能力、配送载重和库存校验。

### 运行中新机器人接入扩展流程

1. 播放或手动推进到 `T=12`，点击暂停，确认“机器人接入”面板可用。
2. 在地图上点击接入位置选择按钮，再点击一个未被障碍、货架、封锁或机器人占用的格；也可以直接输入坐标。以本场景为例，可使用空闲的 `[25,15]`。
3. 填写 `R5`、`运行时巡检车`、电量 `512`、电池上限 `512`、载重 `1`、`moveTicks=1`，只勾选“巡检”，提交接入。
4. 确认地图出现 R5、事件日志出现 `T=12 新机器人接入`，并确认其路径从 T=12 开始；把时间滑回 T=11 时不应显示 R5。
5. 在在线任务面板追加一个目标为 `[24,15]` 的巡检任务，观察 R5 获得任务并移动。继续播放直到任务完成，确认活动冲突、失败、截止超期和意外 `safetyIntervention` 均为零。
6. 点击重置，确认 R5 从地图、当前机器人配置和路径中移除，初始机器人恢复，原始场景动态事件仍可按原时间再次触发。

### 运行中机器人永久退役扩展流程

1. 按上面的接入流程让 R5 完成 `[24,15]` 的巡检任务，确认当前机器人管理中 R5 为“空闲”。
2. 保持在最新会话时间并暂停播放，在“当前机器人管理”中确认 R5 的接入时间、状态和可用的“永久移除”按钮。
3. 点击“永久移除”并完成二次确认；确认 R5 状态变为“已移除”，显示 `移除时间：T=<当前时间>`，事件日志只新增一条永久移除事件。
4. 返回移除时间之前的历史 tick，确认 R5 的退役前轨迹仍可见；返回最新 T，确认当前地图隐藏 R5，R5 不再出现在当前分配和冲突对象中。
5. 继续播放，确认其余机器人可以继续完成剩余任务；再点击重置，确认 R5 和退役记录清除，原始四台机器人恢复。

永久移除只接受空闲、无携货、无未完成硬锁的机器人，等待机器人必须只有未锁定远期任务，故障机器人必须已经完成任务移交；执行中、携货、充电相关、硬锁或最后活动机器人会被后端拒绝。重复移除不重复记录事件，退役机器人不能通过现有故障恢复接口重新启用，且其 ID 不能在同一会话复用。

如果面板处于历史回放、tick 请求中、会话尚未就绪或没有会话，接入和移除控件应禁用。提交成功或失败后都不会自动恢复播放；4xx 输入错误应保留当前会话并在面板显示后端 detail。

## 正式人工录屏路线

录屏只使用最终 `WarehousePatrol.exe` 打开的本地平台，不使用开发服务器、旧构建或旧查询参数入口。画面建议固定为 1920×1080，关闭系统通知和其他窗口，先确认顶部状态显示“后端在线”。所有操作完成后再开始播放或剪辑，保留原始录像。

按下面的时间点暂停并取景；播放速度可以先调高，接近目标 tick 时调低到 `0.2`，用“暂停”固定画面。运行时控件提交会自动暂停播放，提交完成后再继续。

1. 启动 `WarehousePatrol.exe`，等待浏览器打开根路径；确认场景为 `综合调度演示`、策略为“避碰规划”、时间为 `T=0`。
2. 在“机器人接入”面板填写并提交 `R5`：名称“机动协作车”，位置 `[25,15]`，电量 `512`，电池上限 `512`，载重 `1`，每格移动 `1` tick，只勾选“巡检”。确认事件日志记录 `T=0` 接入，R5 出现在当前机器人管理中。
3. 仍在 `T=0` 画面确认 `T1`、`T2`、`T3` 已进入默认流程；播放到 `T=4` 确认 `T4` 到达队列，播放到 `T=8` 确认 `T5` 到达队列，播放到 `T=12` 确认 `E1` 进入调度。
4. 播放到 `T=20` 后暂停。在地图上对空闲单元 `[10,6]` 右键，选择“封锁此单元”；展示受影响任务释放、路径更新和事件日志中的在线重规划。
5. 播放或推进到 `T=28` 后暂停。在 R2 机器人标记上右键，选择“标记 R2 故障”；展示任务移交，确认未分配任务没有增加。
6. 在 `T=36` 先对 `[10,6]` 右键选择“解除封锁”，再对 R2 右键选择“恢复 R2”；展示恢复事件、指标历史和路径重新同步。
7. 继续到 `T=700`，确认六项默认任务完成、13 个货架有货，当前冲突、超期、故障和未分配均为 `0`。
8. 在 `T=700` 通过“在线任务”面板追加人工巡检 `M1`：类型“巡检”，标题“人工追加巡检”，优先级 `4`，截止 `T=760`，作业时间 `2`，目标 `[1,4]`。提交后继续播放，确认 M1 完成。
9. 播放到 `T=706`，在“随机事件生成器”打开“自动生成并推入任务队列”，将生成间隔设为 `6` tick；确认统一任务入口生成 `G1` 配送任务。确认 `G1` 由 R1 接管，`T=718` 到达取货点、`T=727` 完成送达。
10. 在 `T=727` 暂停，展示终态：已完成任务 `8`，当前冲突 `0`，超期任务 `0`，故障机器人 `0`，未分配任务 `0`；同时展示配送货架状态已同步。
11. 保持 `T=727`，在“当前机器人管理”中点击 R5 的“永久移除”，完成浏览器确认；确认 R5 显示“已永久移除”、移除时间为 `T=727`，事件只增加一条退役记录。
12. 点击事件日志中退役前的事件或回到较早 tick，确认 R5 的历史路径仍可见；再点“返回最新 T”，确认最新地图和后续分配不再使用 R5。最后点击“重置”，确认初始机器人集合恢复。

录屏口播按“在线会话与接入 → 默认任务到达 → 封锁与重规划 → 故障与恢复 → 六任务完成 → M1 与 G1 → R5 退役 → 历史回放与重置”的顺序组织。口播只描述画面中实际出现的状态，不把预测冲突、实际执行冲突和安全等待混为一谈。

## 验收点

演示应覆盖以下能力：

- 在线会话创建。
- tick 推进与机器人状态更新。
- 任务目标点作业时间与完成后释放机器人。
- 主演示能查看充电地块、电量与容量；完整低电量充电闭环由专用低电量场景和自动化测试验收。
- 任务锁定。
- 默认六任务在线闭环。
- 四台默认机器人 tooltip 均显示“能力 巡检 / 取送 / 突发”，且所有任务分配都满足 `capabilities`；配送还满足 `robot.load >= task.demand`。
- 后端权威库存和四种货架状态；出库在实际取货时熄灭，入库在放货作业完成后亮起。
- 手工与随机配送使用统一任务端点和同一库存校验。
- 独立扩展测试中的高优先级任务抢占、运行时封锁、机器人故障与恢复。
- 运行中新机器人在真实接入 tick 加入并参与后续任务，接入前历史不显示它，重置后不保留它。
- 运行中机器人在完成任务并满足安全检查后可永久退役；退役后当前地图隐藏它，但退役前轨迹、事件和指标历史仍可回放，重置后恢复初始机器人集合。
- 事件日志解释。
- 指标历史变化。
- 同一综合场景下关闭避碰会出现预测冲突，开启避碰后预测冲突降为0。
- 同一规范化冲突连续被安全门拦截三次后，顶部状态显示“连续拦截 N 次，当前调度停滞”；该字段只负责诊断，不解除全车安全等待。

专项恢复测试中，唯一兼容机器人故障时任务应显示临时 `restoreRobot`；先恢复不兼容机器人不应清除失败，恢复兼容机器人后应自动重规划。该能力约束只改变机器人资格，与尚未实现的全规划时域零冲突保证无关。

避碰验收分为三个层级：一级是代码强制的在线执行安全，开启避碰时会在首个预测顶点或反向边冲突 tick 全车等待，不把冲突动作写入实际路径历史；二级是固定种子与当前综合场景输入的预测冲突为0；三级仍是未实现的全规划时域零冲突保证。大跨度 tick 请求会在首个危险 tick 提前返回，`SessionResult.safetyIntervention` 给出绝对时间、冲突类型、机器人和单元格。

当安全门拦截冲突时，播放自动暂停，顶部显示结构化拦截状态，地图高亮冲突单元和涉及机器人。检查事件后再次播放会从实际等待位置重新规划；系统不会降级执行带冲突路径。`integrated-demo` 默认流程保持不变，强制一维通道仅用于自动化回归，不加入持久化前端场景；基线对比、直接调度和实验接口仍可返回或执行预测冲突，用于对照。
