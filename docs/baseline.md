# P0 基线冻结说明

本文档用于固定当前可运行基线，避免后续模块推进时反复扩大范围或破坏已可演示链路。

## 当前基线目标

当前阶段不是从零开发，而是保护已有在线调度系统，并在此基础上继续补齐模块。

基线通过标准：

- 项目能完成正式前端构建。
- 前端单元测试通过。
- 后端测试通过。
- 固定 demo 端到端测试通过。
- 文档中的演示步骤与自动化验收保持一致。

## 固定演示场景

当前前端固定 1 个主演示场景：

| 场景 ID | 名称 | 用途 |
| --- | --- | --- |
| `integrated-demo` | 综合调度演示 | 同一场景覆盖巡检、取送、避碰、默认在线任务、作业时间、充电、手动封锁、机器人故障和恢复重规划 |

旧的 `campus-warehouse`、`narrow-aisle`、`robot-failure` 场景仍保留在共享场景 JSON 中，供后端固定回归测试使用；前端正式演示入口只暴露综合场景。

## 主线 demo 操作

主线 demo 以 `integrated-demo` 为默认场景：

1. 启用避碰规划。
2. 启用突发任务与重规划。
3. 使用在线会话。
4. 播放到 `T=2` 左右，观察任务锁定。
5. 手动添加突发任务：目标 `(1, 4)`，优先级 `5`，截止时间 `12`。
6. 手动封锁单元 `(1, 2)`。
7. 标记机器人 `R2` 故障。
8. 观察事件日志、任务重分配、机器人状态和指标历史变化。
9. 如需证明避碰价值，在同一综合场景内切换“基线对比”和“避碰规划”，比较冲突数量。

详细步骤以 `docs/demo.md` 为准。

## 验收命令

完整检查：

```powershell
& 'C:\nvm4w\nodejs\npm.cmd' run check
```

固定 demo 端到端测试：

```powershell
.\.venv\Scripts\python.exe -m pytest backend\tests\test_e2e_demo.py -q
```

如果后续改动影响 API、算法、前端类型或演示流程，至少运行完整检查。

## 当前不做的事

P0 阶段不做以下内容：

- 不重写核心算法。
- 不引入完整 MAPF/CBS 求解器。
- 不做 3D 可视化。
- 不做营销式展示页面。
- 不引入持久化、认证或外部监控。

## 下一阶段入口

当前主线已包含速度、载重、电量、充电、作业时间和故障状态。下一阶段优先进入综合演示场景和机器人能力的竞赛级补齐：

1. 统一 `-1` 普通任务和正数高优先级任务规则。
2. 定义任务类型能力并将其作为机器人分配约束；空闲机器人拖动定位等操作细节随该模型补齐。
3. 重做更真实的仓库地图，包括货架区、入库流水线、出库流水线、巡检路线、充电桩和通道布局。
4. 在单独算法分支中评估执行层零冲突安全约束，不与当前基线维护混合。
5. 保持主线 demo 和完整检查持续通过。
