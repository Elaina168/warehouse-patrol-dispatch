# P0 基线冻结说明

本文档用于固定当前可运行基线，避免后续模块推进时反复扩大范围或破坏已可演示链路。

## 当前基线目标

当前阶段不是从零开发，而是保护已有在线调度系统，并在此基础上继续补齐模块。

基线通过标准：

- 项目能完成正式前端构建。
- 前端单元测试通过。
- 后端测试通过。
- 固定 demo 端到端测试通过。
- 文档中的演示步骤与自动化验收保持一致。

## 固定演示场景

当前前端固定 1 个主演示场景：

| 场景 ID | 名称 | 用途 |
| --- | --- | --- |
| `integrated-demo` | 综合调度演示 | 同一场景覆盖巡检、取送、避碰、默认在线任务、作业时间、充电基础设施与状态、手动封锁、机器人故障和恢复重规划 |

共享场景 JSON 只保留 `integrated-demo`。固定回归从该场景的局部变体或独立的最小测试数据验证边界条件，不再保留额外演示地图。

## 主线 demo 操作

主线 demo 以 `integrated-demo` 为默认场景：

1. 启用避碰规划。
2. 使用在线会话；主界面固定启用场景动态机制，不提供动态事件开关。
3. 播放到 `T=2` 左右，观察任务锁定。
4. 手动添加突发任务：目标 `(1, 4)`，优先级 `5`，截止时间 `24`。
5. 手动封锁单元 `(1, 2)`。
6. 标记机器人 `R2` 故障。
7. 观察事件日志、任务重分配、机器人状态和指标历史变化。
8. 如需证明避碰价值，在同一综合场景内切换“基线对比”和“避碰规划”，比较冲突数量。

详细步骤以 `docs/demo.md` 为准。

## 验收命令

完整检查：

```powershell
& 'C:\nvm4w\nodejs\npm.cmd' run check
```

固定 demo 端到端测试：

```powershell
.\.venv\Scripts\python.exe -m pytest backend\tests\test_e2e_demo.py -q
```

如果后续改动影响 API、算法、前端类型或演示流程，至少运行完整检查。

## 当前不做的事

P0 阶段不做以下内容：

- 不重写核心算法。
- 不引入完整 MAPF/CBS 求解器。
- 不做 3D 可视化。
- 不做营销式展示页面。
- 不引入持久化、认证或外部监控。

## 下一阶段入口

当前主线已包含 `0..5` 优先级、速度、载重、电量、充电、作业时间和故障状态。`integrated-demo` 只需展示充电地块、电量和容量，不要求默认流程实际触发充电；低电量专用场景和自动化回归负责验证完整充电闭环。下一阶段入口为：

1. 定义任务类型能力并将其作为机器人分配约束；该三级能力目前未实现。
2. 重做更真实的仓库地图，包括货架区、入库流水线、出库流水线、巡检路线、充电桩和通道布局。
3. 在单独算法分支中评估全规划时域零冲突保证与执行前安全门；二者目前未实现，不与当前基线维护混合。
4. 保持主线 demo 和完整检查持续通过。
