# 自适应滚动重规划窗口实施计划

## 目标

在保留固定窗口默认行为的前提下，为在线会话增加可选的自适应窗口。自适应决策必须同时作用于任务进入规划窗口的过滤和会话滚动窗口触发时间，并向前端返回本轮实际窗口及原因。

## API 契约

- `DispatchOptions.adaptiveReplanWindow: bool = false`
- `assignmentReplanWindow` 继续表示固定模式窗口，或自适应模式的基准窗口。
- `DispatchResult.effectiveAssignmentReplanWindow` 返回本轮实际采用的窗口。
- `DispatchResult.replanWindowReason` 返回固定、收缩、扩大或保持基准窗口的原因。

## 决策规则

固定模式始终使用配置窗口。

自适应模式以配置窗口为基准，并限制在 `4..120`：

1. 最近一次重规划耗时达到 `50ms` 时，收缩到基准窗口的一半。
2. 当前已释放未完成任务数达到可用机器人数量的两倍时，收缩到基准窗口的一半。
3. 当前没有已释放未完成任务、但存在远期任务时，扩大到基准窗口的两倍。
4. 其他情况保持基准窗口。

耗时规则优先于任务压力规则，收缩优先于扩大。任务压力分支对固定输入可复现；规划耗时分支会受运行机器负载影响，因此实验必须同时记录实际耗时、实际窗口和决策原因。既有固定窗口模式继续承担跨环境稳定回归。

## 前端

- 在现有重规划窗口控制旁增加“自适应”开关。
- 状态条显示实际窗口；自适应模式显示调整原因。
- 不增加实验面板。

## 验收

- 固定模式的现有 `24T` 行为完全不变。
- 自适应模式覆盖耗时收缩、任务压力收缩、低负载扩大和基准保持。
- 会话触发时间与本轮实际窗口一致。
- reset 保留配置模式并重新从权威状态计算实际窗口。
- 直接调度、会话、前后端类型和 OpenAPI 契约一致。
- 固定种子和在线压力回归保持零冲突、零失败的既有边界。
- 前端构建、全部前端测试、全部后端测试通过。
