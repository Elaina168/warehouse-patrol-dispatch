# 机器人离散速度调度设计

## 目标

在保持离散网格和现有在线会话 API 的前提下，让不同机器人的移动速度参与任务分配、预计完成时间、路径预约、冲突规避和运行时重规划。

本功能不引入连续坐标、子 tick、跨格移动或连续碰撞检测。任务 `serviceTime` 仍表示机器人到达最终任务目标后额外停留的作业时间，不受移动速度影响。

## 速度模型

机器人新增 `moveTicks` 字段，表示移动一格所需的整数 tick，允许范围为 `1` 到 `3`：

- `1`：快，每 tick 可完成一格移动。
- `2`：标准，每格需要两个 tick。
- `3`：慢，每格需要三个 tick。

移动路径仍由相邻格组成。后端将一次相邻格移动展开为时间路径：机器人在出发格保持 `moveTicks - 1` 个中间 tick，随后到达目标格。例如 `moveTicks=2` 的 A 到 B 移动使用 `[A, A, B]` 表示。

机器人在中间 tick 继续占用出发格；到达目标格后再开始下一次移动。这个规则使所有机器人位置继续严格落在网格格点，现有地图渲染、封锁单元和冲突展示可以保持离散语义。

## 后端行为

### 输入与输出

- 后端 `Robot` 模型、前端 `Robot` 类型和场景 JSON 都包含 `moveTicks`。
- 机器人运行时状态同样返回 `moveTicks`，使前端在会话快照中不依赖静态场景推断速度。
- 场景校验拒绝缺失、非整数或不在 `1..3` 范围内的速度值。

### 分配和时间估计

- 静态可达性仍按格点连通性判断。
- 对候选机器人，移动耗时为网格路径距离乘以该机器人的 `moveTicks`。
- 分配排序、锁定保留、抢占比较、截止超期统计和任务预计完成时间使用移动耗时加 `serviceTime`。
- 载重限制、故障限制、封锁限制和任务优先级规则保持现有语义。

### 时间路径与避碰

- 时间感知 A* 接收机器人移动耗时。
- 等待动作耗时始终为一个 tick；移动动作耗时为该机器人的 `moveTicks`。
- 规划移动动作时，后端检查出发格在中间 tick 的顶点预约、到达格在到达 tick 的顶点预约，以及到达时刻的反向边预约。
- 生成的路径显式包含每个中间 tick 的重复出发格，因此现有预约、冲突检测、路径可视化和机器人位置回放可继续使用路径索引作为绝对时间。
- 机器人故障时仍预约其当前位置；运行时封锁仍拒绝封锁当前占用格。速度较慢的机器人因占用时间更长，可能导致其他机器人等待或被重新规划。

### 在线会话

- 会话推进按展开后的时间路径读取位置、任务进度和任务完成时间。
- 手动任务、随机任务、封锁、故障和恢复都使用当前会话中每个机器人的实际位置与 `moveTicks` 重新规划。
- `serviceTime` 在最后目标格到达后追加，速度不会缩短或拉长作业停留。

## 前端展示

- 默认综合场景中的机器人配置不同 `moveTicks`，以便演示分配差异。
- 地图机器人悬浮信息和机器人运行时信息显示“每格耗时 N tick”。
- 任务队列、事件日志和重规划解释继续使用后端返回的任务状态、路径和完成时间，不在前端重新计算速度或完成时间。
- 播放速度仅控制前端请求 tick 的频率，不改变机器人 `moveTicks` 的调度语义。

## 兼容性与非目标

- 不支持机器人在一个 tick 内跨越多个格点。
- 不支持连续坐标、车辆尺寸、转弯半径、加减速或轨迹插值。
- 已导入场景必须提供 `moveTicks`；导入校验会明确报告缺失或非法值。
- 现有任务、动态事件和恢复 API 的请求结构不变。

## 验证

1. 后端：不同 `moveTicks` 的候选机器人对同一任务按实际完成时间分配。
2. 后端：慢速机器人路径含正确的中间占用 tick，避碰规划无顶点和边冲突。
3. 后端：`serviceTime` 与移动速度叠加，完成时间符合预期。
4. 后端：在线会话在封锁、故障、恢复和新增任务后保持速度语义并可重新规划。
5. 前端：API 类型契约包含 `moveTicks`，地图和运行时信息显示速度。
6. 完整检查：前端构建、前端测试、后端测试和默认综合场景浏览器回归通过。
