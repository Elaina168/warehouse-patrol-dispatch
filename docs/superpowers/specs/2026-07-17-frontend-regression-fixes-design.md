# 前端回归缺陷修复设计

## 背景

平台完整测试确认了三个前端问题：

1. 在 `1280 × 720` 视口下，地图工具栏宽度超过主栏，溢出区域被右侧事件日志遮挡，导致“导出模板”等按钮无法点击。
2. 机器人运行时状态已经转换为中文展示文本后，地图仍用英文状态值判断故障样式，导致 `failed-robot-cell` 永远不生效。
3. 事件日志把“已经开始播放”作为显示前提，导致 T=0 已发生的封锁、故障等事件不能立即显示。

## 目标

- 工具栏在主栏宽度不足时自动换行，所有控件保持可见、可点击。
- 故障机器人所在单元格稳定应用故障视觉样式。
- 所有 `event.time <= currentTime` 的事件立即显示，不依赖是否开始播放；未来事件继续隐藏。
- 不修改后端协议、调度算法、地图数据或现有操作流程。

## 设计

### 工具栏响应式布局

将工作区设为尺寸查询容器。宽度充足时保留现有七列工具栏；主栏实际宽度不足时，通过容器查询切换为可换行的多列布局，并允许控件收缩。判断依据是工具栏所在容器的真实宽度，而不是整个浏览器视口，因此右栏宽度或页面边距变化不会再次制造相同溢出。

验收条件是在 `1280 × 720` 下工具栏不进入右栏覆盖区域，“导出模板”和“导入场景”均可操作；宽屏布局不退化。

### 故障机器人样式

新增一个只接受原始运行时状态的纯判断函数，地图单元格使用该函数决定是否追加 `failed-robot-cell`。中文状态文本只用于 tooltip 和界面展示，不再参与业务状态判断。

### 事件显示

将事件过滤规则统一为 `event.time <= currentTime`。保留现有函数调用兼容性时，不再让播放状态影响结果；随后同步清理无意义的参数和调用。

## 测试策略

遵循先失败、后修复：

1. 修改事件过滤测试，证明 T=0 未播放时的已发生事件当前会被错误隐藏。
2. 为故障状态判断补充纯函数测试，证明 `"failed"` 应产生故障样式判断。
3. 增加浏览器尺寸回归，在 `1280 × 720` 检查工具栏控件未被右栏覆盖且可以点击。
4. 实现最小修复后运行前端定向测试、完整 `npm run check`，并用真实浏览器复测三个场景。

## 非目标

- 不重做平台整体响应式设计。
- 不改变事件排序、事件内容或跳转规则。
- 不改变机器人故障、恢复的后端行为。
- 不清理与这三个问题无关的样式或组件代码。
