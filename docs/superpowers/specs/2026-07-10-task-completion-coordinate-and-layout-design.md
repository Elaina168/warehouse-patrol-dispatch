# 同坐标任务完成、坐标输入与侧栏布局设计

## 目标

修复同一机器人连续执行同坐标任务时，首个任务完成会导致后续任务被同时标记为已完成的问题；简化在线任务的坐标输入；调整运行监控模块的展示位置，使任务队列获得最右侧主要纵向空间。

## 已确认范围

- 同一机器人连续任务不能在同一 tick 被判定完成，即使前后任务目标坐标相同。
- 坐标输入暂时保留离散格点语义，使用一个文本输入框填写一组坐标，例如 `3, 0`。
- 地图侧栏顺序为：指标、重规划解释。
- 页面最右侧栏上方为事件日志，约占三分之一；下方为任务队列，约占三分之二。
- 保持地图画布尺寸、现有会话 API 和任务队列未完成/已完成双列结构不变。

## 根因与完成语义

当前会话路径和任务完成计算均允许后续任务从前一任务已使用的同一路径索引开始查找目标。当前后任务目标相同，后续任务会复用前一任务的到达 tick，因此在首个任务完成时被一并标为完成。

采用“任务边界至少推进一个 tick”的语义：

1. 同一机器人后续任务的目标查找从前一任务完成 tick 的下一 tick 开始。
2. 当路径规划发现后续任务的首个目标就是当前机器人位置时，路径补入一个停留 tick，保证该后续任务有真实的独立执行时刻。
3. 同一机器人不同目标任务仍可在移动的相邻 tick 连续完成；不同机器人可在同一 tick 并行完成各自任务。
4. 直接规划完成时间、在线会话完成状态、锁定开始时间与局部进度计算共用同一任务边界规则，避免重规划后再次产生批量完成。

这避免了为每个任务强制增加全局服务时长，从而不必要地改变所有截止时间和既有调度成本。

## 坐标输入

在线任务表单中的目标、取货与送达坐标均替换为单个文本字段。

- 接受格式：`x,y`，允许逗号两侧空格。
- 提交时在前端解析为后端现有的 `Cell` 数组。
- 格式错误、非整数或超出当前地图范围时，在前端阻止请求并给出明确错误。
- 任务类型切换时保留各字段的输入值。

后续连续坐标或地图点选不在本次范围内。

## 布局

桌面布局调整如下：

```text
地图工作区右侧：
  指标
  重规划解释

页面最右侧：
  事件日志（上方约三分之一）
  任务队列（下方约三分之二）
```

最右侧栏自身采用纵向网格：事件日志位于顶部，高度约占三分之一；任务队列位于下部，高度约占三分之二。地图侧栏保留指标与重规划解释，且重规划解释紧跟在指标之后。

移动端继续由现有断点改为单列堆叠，不改变地图画布尺寸。

## 测试

- 后端：创建同一机器人可顺序执行的三个同目标巡检任务，逐 tick 推进；首个完成时，后两个任务不得处于 completed 状态，三项任务完成时间必须严格递增。
- 后端：重规划后重复验证该任务边界，防止重建路径再次复用旧 completion tick。
- 前端：测试坐标字符串解析、格式错误和超界拒绝，以及手动任务构建结果仍符合现有任务类型结构。
- 前端：测试任务队列和事件日志组件位置由结构性 class 标识区分，防止布局回退。
- 完整检查：前端构建、前端测试、后端测试，并在浏览器确认右侧纵向分区和重复任务状态。
