# 活跃路径与任务队列设计

## 目标

改善在线仿真中的路径可读性和任务队列可扫描性：未启动仿真时不显示规划路径；运行或重规划后，仅显示机器人当前任务的剩余行进方向；将任务按未完成和已完成分栏展示。

## 范围

- 前端地图路径覆盖层、仿真启动控制、任务队列和在线任务面板。
- 不修改后端调度、路径规划、会话 API 或场景数据。

## 路径显示

### 交互规则

- 新建或重置会话后，地图不显示任何路径提示。
- 首次点击“播放”后，启用路径提示；暂停后保留当前提示，重置后再次隐藏。
- 仅当机器人存在当前执行中的任务时显示其路径提示。任务完成、机器人故障、任务未到达或未分配时，不显示该任务的提示。
- 在线重规划返回新结果后，已启用的路径提示立即切换到新路径；不会保留旧路径。

### 图形规则

- 不绘制整条连续折线。沿当前任务尚未经过的路径片段显示离散小箭头，箭头指向下一格。
- 每个箭头定位到下一目标单元的中心，位置复用实际网格内容区域、行列数和 `gap`，不能使用独立百分比 SVG 坐标换算，也不覆盖机器人所在格。
- 不同机器人沿用既有路径颜色。相同路段的箭头按机器人序号作轻微法线偏移，避免完全重叠；机器人所在格不显示箭头。
- 当前任务完成后，所属机器人的箭头在下一次状态渲染中消失。后续任务进入执行状态后才显示其箭头。

### 数据边界

- 路径来源仍是 `DispatchResult.paths`。
- 当前任务优先使用 `SessionResult.robotStates[].currentTaskId`；没有运行时快照时，使用任务的 `releaseTime`、路径到达各任务终点的时间和任务分配顺序推导。
- 当前任务对应的路径范围从当前时间的机器人位置开始，到该任务最后一个目标点首次到达的位置结束。巡检任务覆盖其未完成目标点；取送任务覆盖取货和送达阶段；突发任务覆盖其单个目标点。

## 仿真控制

- 将播放速度的拖动条改为数字输入框，标签为“播放速度（tick/s）”。
- 默认值保持当前约 `2.4 tick/s` 的节奏；输入允许小数，步长为 `0.1`，有效范围为 `0.2` 到 `10`。
- 输入值转换为内部毫秒间隔；无效、空值或越界值不会写入播放状态。

## 任务队列

- 将地图右侧栏从 `320px` 扩为 `460px`，保证任务信息在桌面宽度下可读。
- “任务队列”内使用两个等宽列：左列“未完成”，右列“已完成”。窄屏沿用已有单列响应式布局，未完成列在前。
- `pending`、`active`、`unassigned` 任务进入未完成列，保持现有状态排序和详情展开行为。
- `done` 任务进入已完成列，按完成时间和任务 ID 排序，默认折叠；展开后保留到达、截止、完成时间及原有详情。
- 同一次在线 tick 或重规划造成任务状态变化时，任务立即从未完成列移动到已完成列。

## 在线任务面板

- 删除会话编号、当前时间、任务计数、封锁数和故障数构成的底部说明文字。
- 保留“加入任务并重规划”和“推入自动任务流”按钮及其可用性条件。

## 验收与测试

- 单元测试覆盖：未启动时路径提示为空；启动后只返回活跃任务的剩余箭头；任务完成后箭头消失；重规划后使用新路径；任务按未完成和已完成拆分；速度输入只接受有效 `tick/s` 值。
- 构建与现有前端测试必须通过。
- 手工验证：在综合调度演示中检查初始无箭头、播放后箭头对齐网格、动态重规划后箭头更新、任务完成后移动并折叠，以及窄屏单列布局。

- 已实现：播放速度改为 `tick/s` 数字输入，合法范围为 `0.2` 至 `10`。
- 已实现：任务队列拆分为未完成和已完成两栏，已完成项默认折叠；在线任务面板已移除会话统计说明。
