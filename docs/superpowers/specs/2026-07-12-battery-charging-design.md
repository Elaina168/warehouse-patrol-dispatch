# 硬电量约束与充电闭环设计

## 目标

在现有离散网格、在线会话和时间路径预约模型中加入物理充电闭环。机器人按实际跨格移动消耗电量；调度器只分配能够完成任务全部目标并到达可达充电桩的任务。当电量不足以满足该安全条件时，机器人先前往充电桩，在充电期间不可执行任务，充满后再参与后续调度。

本功能保持当前离散 tick 语义。`moveTicks` 只影响一格移动占用的时间，不改变该次跨格移动的耗电量；`serviceTime` 只影响到达最终任务目标后的作业停留，不消耗电量。

## 范围与非目标

本分支包含：充电地块、当前电量与满电容量、前往充电和充电中状态、充电路线规划、充电等待、避碰预约、在线重规划、事件日志、前端地图和回归测试。

本分支不包含：电池健康衰减、不同类型充电桩功率、排队共享同一个充电格、手动修改电量、外部充电管理系统，或连续物理能耗模型。

## 数据模型

### 地图区域

`Zones` 新增 `charging: list[Cell]`。充电格是可通行的固定功能地块，不是障碍，也不能被运行时封锁为普通封锁单元。综合演示场景提供至少两个充电格，位于可从主通道抵达的位置。

`Scenario` 新增可选正整数 `chargeTime`，表示一次完整充电所需的 tick，缺失时默认 `4`。默认综合场景显式设置为 `4`，导入旧场景则按该默认值兼容。

为保持旧导入场景可读，缺失 `zones.charging` 时解析为一个空列表，并视为未启用充电闭环：后端仍限制任务移动距离不超过当前剩余电量，但不要求返航充电，也不生成充电状态。只要场景定义至少一个充电格，就启用完整的“完成任务后可达充电桩”安全约束；默认综合场景始终使用该完整约束。后端不会将机器人起点隐式当成充电桩。

### 机器人电量

`Robot.battery` 表示会话创建时的剩余电量；新增可选 `Robot.batteryCapacity`，缺失时为 `100`。约束为 `0 <= battery <= batteryCapacity`。运行时状态返回当前 `battery` 与 `batteryCapacity`。

一次从一个格子移动到相邻格子消耗 `1` 点电量。等待、任务 `serviceTime`、前往任务之前的静止和充电等待均不消耗电量。机器人移动速度不会改变单格耗电量。

### 运行状态

机器人运行状态新增：

- `toCharge`：沿后端规划的时间路径前往充电格。
- `charging`：已经到达充电格，正在完成场景 `chargeTime` tick 的充电等待。

充电完成后，当前电量恢复为 `batteryCapacity`，机器人转入 `idle` 或 `waiting`。`toCharge` 和 `charging` 均视为不可接收任务的运行状态；前端拖动和右键恢复等已有交互遵循现有不可用机器人规则，不允许将充电中的机器人作为可调度对象。

## 调度与路径规则

### 安全余量触发

不使用固定百分比阈值。对每一个候选任务，后端计算：

1. 当前机器人位置到任务全部目标的移动距离。
2. 任务最后目标到最近可达充电格的移动距离。
3. 任务服务时间后的剩余电量。

只有当当前电量不少于两段移动距离之和时，机器人才能领取任务。配送任务按“当前位置到取货点、取货点到送达点、送达点到充电格”的完整顺序计算。巡检任务按全部巡检点顺序计算。紧急任务按当前位置到目标、目标到充电格计算。

如果当前电量不足，但机器人能先到达某个充电格，则调度器把充电路线排在该机器人下一段时间路径中，完成充电后再重新参与任务分配。如果机器人无法到达任一充电格，则不再向其分配任务，并以“剩余电量不足且无可达充电桩”作为可解释原因。

机器人完成任务后，若存在已释放的候选任务而剩余电量不足以完成该任务并返航充电，后端先规划返航充电，再参与任务分配。没有已释放待执行任务时，机器人保持原位，不为展示目的产生无意义的充电移动。

### 时间路径、避碰与重规划

前往充电格的路段使用与普通任务相同的时间感知 A*、动态封锁、故障机器人占位和路径预约。充电等待通过在充电格重复写入 `chargeTime` 个 tick 表示，因此其他机器人不能在同一充电格同一时刻重叠。

在线会话把当前电量作为真实运行状态保存，而不是从初始电量减总距离推导。每次 tick 只对实际发生的跨格移动扣电；每次完成充电才恢复到容量上限。运行时封锁、机器人故障、手动任务和随机任务进入会话后，后端以机器人当时的位置、电量和充电状态重新规划。

若重规划后通往充电格的路线被封锁，后端保留任务的真实状态并记录可解释的电量/充电不可达原因；不会为了继续派发任务而透支电量或穿过封锁地块。

## 可观测性

### 事件与解释

事件日志仅在实际状态变化时记录：电量不足触发返航、开始充电、完成充电、因充电不可达而暂缓任务。预测路径不会提前产生这些事件。

重规划解释区显示充电中的机器人数量，并在存在充电不可达任务时展示该原因。任务队列继续使用后端任务状态；因所有可用机器人处于充电或电量不足而暂时无法派发的任务保持“等待分配”，而非误报为永久失败。

### 地图与机器人信息

地图为充电格提供稳定的功能地块标识，不改变画布尺寸或可通行区域。机器人悬浮信息显示“当前电量 / 容量”和运行状态；`toCharge` 与 `charging` 具有明确中文状态标签。机器人图标始终保持在路径箭头和充电格标识上方。

## 验证

1. 模型与 API 契约：`charging`、`chargeTime`、`batteryCapacity`、新增运行状态在后端 Pydantic 模型、前端 TypeScript 类型和 OpenAPI 契约测试中一致；旧场景缺失新字段时按 `chargeTime=4` 和空充电格列表解析。
2. 任务分配：电量不足以完成任务并返航的机器人不会获得该任务；充电后可以获得任务；容量不足以完成完整任务加返航时任务有明确不可调度原因。
3. 会话执行：实际移动才扣电，`moveTicks` 不改变每格耗电；`serviceTime` 不扣电；充电等待结束后电量恢复为容量。
4. 避碰：两台机器人前往同一充电格时，时间预约避免顶点和边冲突；充电格等待也被预约。
5. 在线重规划：运行时封锁充电路线、机器人故障、手动新增任务和随机任务都基于当前电量重新规划，且事件日志时间与实际 tick 对齐。
6. 前端：综合场景显示充电格，机器人信息显示电量容量和充电状态，任务队列与重规划解释正确反映充电导致的等待。
7. 完整检查：前端构建、前端测试、后端测试和默认综合场景浏览器回归通过。
