# 任务流、静止启动与随机生成器设计

## 背景

当前前端的“推入自动任务流”和“加入任务并重规划”是两个不同入口：

- “加入任务并重规划”会把表单中的任务提交给后端会话。
- “推入自动任务流”只调用后端自动生成任务接口，由后端按序号生成 `A*` 任务。

这导致人工测试时容易误解为“我刚填写的在线任务没有进入任务队列”。同时，仿真启动前任务已经出现执行中状态，破坏了“仿真开始前系统静止”的演示语义。

第一阶段只处理任务流、初始状态和随机任务生成器，不引入机器人拖动、速度、电量、充电、服务时间或新仓库地图。

## 目标

1. 手动填写任务后，只有一个主要动作：推入任务队列。
2. 推入任务队列后，事件日志、任务队列、重规划解释和地图路径都由同一份后端会话结果驱动。
3. 仿真开始前，所有初始任务保持等待状态，不提前显示执行中。
4. 仿真开始后，才进行任务分配、锁定、路径规划和状态推进。
5. 新增随机事件生成器，用于按间隔自动生成任务并推入任务队列，方便压力测试。
6. 移除独立“自动任务流”能力，不再保留和手动任务并行的第二套入队语义。

## 非目标

以下内容暂不在第一阶段实现：

- 鼠标拖动机器人位置。
- 右键机器人故障和解除故障。
- 冲突机器人分离式人工恢复。
- 任务服务时间。
- 机器人不同速度。
- 电量、充电桩、充电占用。
- 默认仓库地图重做。
- 优先级规则大改。
- 播放速度滑条恢复。

这些功能会在任务流稳定后单独设计和实现。

## 交互设计

### 手动任务

在线任务表单保留任务类型、标题、优先级、截止时间和坐标输入。

按钮改为：

```text
推入任务队列
```

点击后：

1. 前端校验坐标和任务字段。
2. 前端调用后端统一任务入队接口。
3. 后端以当前会话时间记录任务到达事件。
4. 后端重新构建任务状态。
5. 如果仿真尚未开始，新任务进入等待队列，但不触发执行状态。
6. 如果仿真正在运行，新任务进入调度队列并触发重规划。

### 随机事件生成器

新增一个独立开关：

```text
随机任务生成器
```

控制项：

- 是否启用。
- 生成间隔，单位为 tick。
- 随机种子，默认可为空；测试时可填写固定值。

启用后：

1. 仿真播放时，每隔 N tick 生成一个随机任务。
2. 随机任务生成完整任务对象后，走和手动任务完全相同的任务入队路径。
3. 随机任务生成后必须出现在事件日志和任务队列中。
4. 随机任务不直接修改前端本地任务列表。
5. 随机生成器只负责自动生成和自动推入，不拥有独立调度能力。

第一版随机类型：

- inspection：从巡检区域或可通行单元中选目标。
- delivery：从仓储区和投递区中选 pickup/dropoff。
- emergency：从可通行单元中选目标，并给正优先级。

第一版优先级规则：

- 普通随机任务优先级固定为 `-1`。
- 突发随机任务优先级为正数，第一版在 `1` 到 `5` 之间生成。
- 正数越大越优先。
- 已有默认场景任务的优先级数值暂不迁移，避免把任务流修复和场景重做混成同一次改动。

## 后端行为

系统只保留一个任务入队语义：接收完整任务对象，将任务加入当前会话队列，并返回完整 `SessionResult`。

手动在线任务和随机生成任务的区别只在前端来源：

- 手动在线任务由用户填写表单后点击“推入任务队列”。
- 随机生成任务由随机事件生成器自动构造任务对象并自动调用同一个推入流程。

统一任务入队必须：

- 使用后端会话当前时间作为事实时间。
- 写入 runtime event。
- 更新任务计数。
- 返回完整 `SessionResult`。
- 不允许让前端局部伪造任务队列或事件日志。

原有独立 `stream-task` 能力不再作为产品能力保留。实现时应移除前端入口，并清理或废弃后端对应接口，避免后续测试再次调用到旧语义。

如果仿真尚未开始，后端可以接收任务并返回等待状态；但不得把任何任务标记为执行中。

## 初始静止状态

会话创建后的默认状态应满足：

- 当前时间为 `0`。
- 所有初始任务为等待或未释放状态。
- 无已锁定执行任务。
- 地图不显示运行路径箭头。
- 事件日志只显示必要的会话创建信息；不显示未来动态事件预测。

首次点击播放、单步推进或显式重规划后，系统才进入调度状态。

## 默认动态流程说明

当前综合场景默认动态事件保持不变：

- `T=12` 触发。
- 封锁 `(6,3)` 和 `(7,5)`。
- `R3` 故障。
- 释放突发任务 `E1`，目标 `(7,9)`，优先级 `5`。

这部分应在前端或测试文档中明确展示，避免人工测试时误认为系统随机封锁了地块。

## 错误处理

- 坐标非法：前端阻止提交并提示坐标格式。
- 后端拒绝任务：前端显示后端返回的具体错误。
- 随机生成失败：写入事件日志或前端状态提示，不得让播放循环卡住。
- 连续点击：按钮进入提交中状态，避免重复请求造成卡顿或重复任务。
- 会话时间不同步：以后端返回的 `currentTime` 为准。

## 测试要求

后端测试：

- 创建会话后初始任务不处于执行中。
- 仿真启动前插入手动任务后，任务进入等待队列和事件日志。
- 仿真运行中插入手动任务后，触发重规划并保持时间不回退。
- 随机生成器生成的任务对象通过同一个任务入队流程进入队列。
- 随机任务生成使用 seed 时可复现。
- 随机任务生成不会选中障碍、封锁或越界坐标。
- 连续随机任务 ID 不重复。
- 旧 `stream-task` 产品入口不再可用，测试不应依赖旧自动任务流接口。

前端测试：

- 表单按钮文案为“推入任务队列”。
- 手动任务提交调用统一任务入队流程，不调用旧 stream-task 逻辑。
- 随机生成器自动构造任务对象后调用统一任务入队流程。
- 随机任务生成器启用时按间隔触发。
- 随机任务生成器关闭时不触发。
- 初始会话任务队列显示等待状态。

人工测试：

1. 打开平台，不播放，确认任务队列没有执行中任务。
2. 不播放时推入一个手动任务，确认事件日志和任务队列出现该任务，但地图不显示运行路径。
3. 点击播放，确认任务开始分配并显示路径。
4. 播放中推入手动任务，确认事件日志、任务队列、重规划解释同步更新。
5. 开启随机任务生成器，确认任务按间隔进入队列。
6. 关闭随机任务生成器，确认不再新增随机任务。
