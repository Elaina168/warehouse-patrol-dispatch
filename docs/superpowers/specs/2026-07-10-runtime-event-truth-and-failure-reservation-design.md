# 运行事件真实性与故障机器人占位设计

## 目标

使在线会话日志只反映已经发生的运行事件，消除未来规划预测造成的错误时间顺序；使故障机器人在故障发生后以其实际停留位置参与后续避碰重规划；压缩指标模块并扩展任务队列的可用空间。

## 范围

- 修改后端会话事件汇总、运行推进、路径规划保留和规划日志生成。
- 修改前端事件日志可见性与地图侧指标/任务队列布局。
- 不改变场景动态事件的触发时间、任务分配接口、路径坐标系或固定地图画布尺寸。

## 事件日志语义

- 在线会话日志以会话实际事件为唯一来源：任务录入、自动任务到达、任务开始锁定、任务实际完成、封锁/解锁、故障/恢复、动态事件激活、滚动窗口纳入和真实冲突检测。
- 会话不再混入 `run_dispatch` 生成的完整规划期预测日志；因此不会提前显示未来任务分配、预计按时完成、未来动态触发或“未检测到冲突”。
- 任务在推进到其实际完成 tick 时写入一次完成事件；任务锁定仍在实际执行窗口开始时写入。
- 仅当当前规划结果包含冲突时，在线日志写入一次冲突检测事件；不再记录“未检测到时空路径冲突”。
- 直接规划 API 的日志仅保留当前时刻的规划配置、失败和已检测冲突，不再产生带未来 tick 的成功预测事件。
- 前端在首次播放前不渲染事件日志；首次播放后只渲染事件时间不超过当前回放 tick 的条目。

## 故障机器人与重规划

- 故障事件发生时，会话先推进到事件 tick，再读取该机器人实际位置，记录故障并使其不可用。
- 仅在故障发生后的重规划中，路径规划器将不可用机器人当前起点作为全规划期的时空保留位置；其他机器人不能进入该单元。
- 故障发生前，机器人继续按正常时空路径参与避碰，不预先作为静态占位。
- 恢复机器人后，该机器人不再属于不可用集合，下一次重规划自动移除其静态保留。
- 固定回归使用综合场景：推进至 `T=32`，R3 已故障停在 `(4,4)`；新增巡检任务 `(3,0)`、优先级 3，并推入自动任务流。R4 后续路径不得进入 `(4,4)`，且冲突数必须为 0。

## 地图侧布局

- 指标模块保持八项实时指标，但降低单卡高度、内边距、数值字号和卡片间距。
- 任务队列的可滚动高度增加，优先显示更多未完成任务。
- 不调整地图画布、任务队列双列结构或移动端单列断点。

## 验收

- 未开始播放时，前端事件日志为空；播放后只显示已到达当前 tick 的实际事件。
- 日志中不再出现“未检测到时空路径冲突”或规划预测的“均按时完成”。
- 任务完成、故障、封锁、手动任务和自动任务流均在实际发生时记录。
- 固定故障回归中 R4 不进入 R3 的故障位置 `(4,4)`，整个后续流程保持零冲突。
- 前端测试、后端测试、构建和完整项目检查通过。
