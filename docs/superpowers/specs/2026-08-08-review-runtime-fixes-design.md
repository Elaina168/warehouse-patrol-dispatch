# 全量审查运行问题修复设计

## 目标

修复 2026-08-08 全量代码与文档审查中确认的八个非界面设计问题，同时保持当前在线调度、默认演示、实验接口和离线报告的既有行为边界。第 6 项键盘/读屏交互和第 8 项告警颜色属于已确认不处理的设计选择，本次不得修改。

## 全局约束

- 项目唯一受支持的 PowerShell 主版本为 PowerShell 7；官方命令统一调用项目内 `.\.tools\powershell\pwsh.exe`。
- Windows PowerShell 5.1 不属于兼容范围，直接运行项目脚本时必须得到明确的版本错误。
- 所有生产行为修改必须先有能够复现问题的失败测试，再实施最小修复。
- 不修改既有 `output/`，不进行无关重构，不改变前端地图交互和安全告警视觉设计。
- 标识符匹配保持精确，不进行大小写、格式或结构猜测。

## 修复设计

### 1. 区分移动距离与时间路径长度

时间展开路径继续保留重复坐标，用于表示释放等待、服务等待、充电等待、避碰等待和 `moveTicks`。`makespan` 继续使用路径的 tick 长度；`totalDistance`、基于路径距离的 `loadBalance`，以及候选评分中的距离和距离均衡维度，只统计相邻坐标发生变化的次数。

测试必须覆盖至少一个只移动 1 格但包含释放等待的路径，并分别断言 `makespan` 与 `totalDistance`。还应覆盖 `moveTicks > 1`，防止慢速移动的重复坐标再次污染距离。

### 2. 保证最终报告提交边界的数据完整性

算法 benchmark 与自适应校准 reporter 采用相同的事务判定：当所有最终文件已经发布、对应临时文件均不存在且 `results.partial.json` 已经删除时，发布已经提交。此后即使文件删除调用在完成后抛出 `KeyboardInterrupt` 或 `SystemExit`，也不得删除新最终文件或恢复旧 bundle。

调用方仍可收到原取消异常，但已完成的新报告必须保留，事务备份和临时文件必须清理。测试必须覆盖全新目录和已有旧 bundle 两种情况。

### 3. 场景导入采用候选提交模型

读取并解析导入文件后，候选场景不得立即替换当前活动场景、会话或结果。前端先使用候选场景向后端创建会话；只有创建成功后，才一次性提交候选场景及返回的会话结果，并按既有所有权规则处理旧会话。

候选创建失败时，当前场景、当前会话、结果、播放时间和操作视图全部保持不变，只更新导入错误状态。过期响应必须继续受现有请求协调器保护，不能覆盖更新的用户操作。

### 4. 拒绝空白身份字段

后端与前端对以下字段应用一致规则：场景 ID、场景名称、机器人 ID、机器人名称、任务 ID、任务标题、货架 ID、动态故障机器人 ID、运行时机器人 ID 和实验标签不得为空串或纯空白。

非空字符串保持原值，不静默修剪、改写大小写或规范化。描述字段继续允许空串。重复检查继续按精确字符串执行。

### 5. 固定 PowerShell 7 运行入口

VS Code 启停任务、README、环境文档和仓库级操作说明统一使用项目内 PowerShell 7。公共脚本入口在执行任何清单读写或进程操作前检查 `$PSVersionTable.PSVersion.Major -ge 7`，不满足时给出包含项目内 `pwsh.exe` 精确调用方式的错误。

现有 npm 脚本继续作为推荐入口。验证必须分别证明项目内 PowerShell 7 校验通过，以及 Windows PowerShell 5.1 在产生运行副作用前失败。

### 6. 动态重规划实验按实际分支校验

`POST /api/experiments/dynamic-replanning` 必须按照实验实际执行的动态分支进行场景校验。请求中的 `options.includeDynamic` 不得绕过随后必定运行的 `includeDynamic=true` 案例。

包含无兼容机器人或静态不可达动态任务的请求，无论传入的 `includeDynamic` 是 `false` 还是 `true`，都必须在调用比较函数之前返回 `422`。

### 7. 限制本地场景导入大小

前端在调用 `file.text()` 前检查 `File.size`，最大允许值固定为 `2_097_152` 字节，与后端请求体限制一致。超过限制时不得读取或解析文件，不得修改活动场景或会话，并显示包含允许大小的确定性错误。

恰好位于边界的文件仍进入正常解析流程。

### 8. 保证 Scale 实验标签非空且唯一

`ScaleExperimentRequest.cases[*].label` 必须满足非空白规则，并在同一请求内按精确字符串唯一。重复标签在运行任何实验案例前由模型校验拒绝。

由于不进行静默修剪，`"case"` 与 `" case "` 是否相同不作猜测；二者均为非空字符串并按原值精确比较。纯空白标签始终拒绝。

## 测试与验收

实施按两个批次进行：

1. 主运行批次：距离语义、事务式导入、空白字段、导入大小限制、PowerShell 7。
2. 离线与实验批次：报告提交边界、动态实验校验、Scale 标签唯一性。

每项执行 RED、GREEN 和相关回归测试。全部完成后至少运行：

- 前端完整测试与生产构建。
- 后端完整 pytest。
- PowerShell 7 `start-dev.ps1 -ValidateOnly`。
- Windows PowerShell 5.1 版本拒绝测试，确认无清单或进程副作用。
- `pip check`、npm 官方源审计、`git diff --check` 和 Markdown 本地链接检查。

验收时逐项重新执行原始复现：等待路径移动距离为 1、导入失败保留旧会话、空白字段被拒绝、超大文件不被读取、两套 reporter 在 partial-delete 取消后保留完整 final、动态实验返回 `422`、重复 Scale 标签被拒绝。
