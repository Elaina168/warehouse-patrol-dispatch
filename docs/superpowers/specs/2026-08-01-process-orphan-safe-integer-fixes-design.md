# 开发进程孤儿清理与安全整数导入修复设计

## 目标

修复两项复审发现：开发服务根进程提前退出后，`stop-dev.ps1` 仍能清理已确认归属项目的存活后代；前端场景导入拒绝 JavaScript 无法精确表示的整数。修复不改变调度算法、API 路由、端口配置或未跟踪的 `output/`。

## 进程所有权设计

`.runtime/dev-processes.json` 继续保存 `role`、`pid` 和 `startedAtUtc`，不引入端口扫描、命令行模糊匹配或仅凭 PID 的终止逻辑。新增进程树同步操作：在根进程仍可验证时捕获其后代，为根和每个后代分别写入精确身份；相同 PID 与启动时间的记录幂等更新，不重复追加。

`start-dev.ps1` 在启动登记、服务就绪和主监控循环中同步已启动进程树，使 Node/Vite 与 Uvicorn worker 在根进程异常退出前进入 manifest。停止时逐条重新验证 PID 与启动时间：匹配项才允许终止；身份不匹配项保留；已不存在项移除。根进程在已取得句柄后退出、导致 CIM 根行消失时，后代捕获使用该句柄给出的根 PID 与启动时间继续构建树，而不是返回空数组。

如果根进程在任何一次树同步前就退出，系统不得通过端口或猜测恢复所有权；启动流程应失败并保留可确认的记录。该边界保持“宁可报告无法确认，也不误杀无关进程”。

进程树同步只保证清理由某次 CIM 快照确认并写入 manifest 的后代。若瞬态中间包装进程及其后代在两次快照之间完成创建、且中间进程在下一次快照前退出，系统不会跨缺失的父进程行猜测认领从未观察到的后代。CIM 快照在 manifest 锁内执行，以避免停止事务完成后又写回旧身份；查询设置 5 秒操作超时，短于 10 秒锁等待预算，异常时由互斥锁的 `finally` 释放锁且不写入部分 manifest。

## 场景整数设计

`frontend/src/domain/scenarioImport.ts` 的通用整数范围判断改用 `Number.isSafeInteger`。所有复用该函数的坐标、尺寸、时间、电量、载重、需求量和优先级字段因此统一要求可被 JavaScript 精确表示；既有有限上限保持不变。

后端仍是最终验证权威。本次不为后端无界整数另设业务上限，因为 Python 能精确表示 JSON 整数，当前缺陷发生在浏览器解析阶段。

## 错误处理与兼容性

- manifest 写入与停止操作继续使用现有互斥锁和临时文件替换。
- 清理只依赖经过 PID 与启动时间双重验证的条目。
- 旧版仅含根条目的 version 1 manifest 仍可读取；运行中的新启动流程会逐步补充后代条目。
- 场景字段位于安全整数范围内时，导入行为不变；超出范围时继续使用现有 `JSON 必须是 Scenario 对象` 错误入口。

## 测试设计

1. 在 `backend/tests/test_dev_scripts.py` 新增真实进程回归：根进程创建长寿命子进程；树同步后根进程先退出；`Stop-RecordedProcessTree` 必须终止子进程并清空已处理记录。测试 `finally` 负责兜底清理。
2. 新增 CIM 根行缺失的单元回归，验证已持有根身份时仍可从进程快照识别后代。
3. 在 `frontend/src/domain/scenarioImport.test.ts` 新增超出 `Number.MAX_SAFE_INTEGER` 的 `battery`、`demand` 或 `deadline` 导入拒绝回归。
4. 先运行新增测试确认失败，再实现最小修复；随后运行开发脚本测试、场景导入测试、前端构建、完整 `npm run check`、`pip check` 和 `git diff --check`。

## 非目标

- 不按端口终止进程。
- 不通过进程名、命令行或路径猜测所有权。
- 不新增持久化服务、数据库或第三方依赖。
- 不提交、合并或推送分支。
